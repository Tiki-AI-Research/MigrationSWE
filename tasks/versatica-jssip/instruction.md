## Background

JsSIP ships a generated SIP grammar parser as part of its public `Grammar` surface. The checked-in parser is produced by PEG.js 0.7.0 from the repository's grammar source. PEG.js 0.7.0 is unmaintained and does not run reliably on current Node.js versions, and a consumer of the package can no longer rebuild the checked-in parser from its grammar source with the declared toolchain. Replacing the generator must not change anything that consumers observe.

## Goal

Migrate grammar parser generation entirely from PEG.js 0.7.0 to Peggy 4.2.0 so that the checked-in parser is the reproducible output of that generator, no PEG.js 0.7.0 remains active in the dependency tree or build path, and every public parsing contract and parsing result stays identical to the PEG.js 0.7.0 baseline.

## Public contract to preserve

- The target generator MUST be declared as a development dependency at exactly the target version in the package manifest, and the lockfile MUST resolve that package at the target version from a normal registry tarball with a `sha512` integrity hash.
- PEG.js 0.7.0 MUST be absent from the manifest, from the lockfile root, from every resolved package identity in the lockfile, and from the grammar build path. Keeping it under a different dependency key, an npm alias, a renamed installed package, or a vendored copy does not satisfy the contract.
- The project's grammar build MUST complete using the project-local target toolchain and MUST NOT use PEG.js. Running the documented grammar build from the repository root MUST produce the committed parser artifact.
- The grammar source MAY be adapted where it depends on PEG.js 0.7.0-only facilities that Peggy 4.2.0 does not provide, but the accepted language, the start-rule set, and the produced semantic results MUST stay those of the baseline.
- The committed parser artifact MUST be reproducibly produced from the grammar source by the project's target-version grammar build. Rebuilding it MUST reproduce the committed file byte for byte.
- A successful parse MUST return the accumulated semantic result for the selected start rule.
- `parse` MUST accept both historical call shapes: `parse(input, startRule)` with a string start rule and `parse(input, options)` with an options object. A syntax error MUST return `-1`. An unknown start-rule name MUST throw a plain `Error` from both call shapes; any other exception MUST propagate unchanged in type and message.
- The options object's `startRule` property MUST be read exactly once per parse call; the value that is validated MUST be the value used. Read it with normal JavaScript property lookup, including inherited properties. An inherited unknown or non-string `startRule` value MUST be validated and quoted exactly like an own value.
- The historical start-rule shape applies to every non-object second argument except `null` and `undefined`, and to genuine boxed `String`, `Number`, or `Boolean` objects and functions. Such a value MUST be converted with `String` and validated against the declared start-rule names. A resulting declared rule name MUST be accepted; only an unknown resulting name MUST be rejected with the quoted unknown-rule error. A function's `startRule` property MUST NOT be used in the historical shape. Only other objects use the options shape.
- A boxed primitive is recognized by its internal type, not by `instanceof`: boxes created in another realm still qualify, while objects that merely inherit `String.prototype`, `Number.prototype`, or `Boolean.prototype`, and `Proxy` wrappers around boxes, do not. The selected value MUST be coerced with `String`; do not replace that coercion with a manual `valueOf` or `toString` call. Exceptions raised by coercion MUST propagate unchanged.
- The parser MUST ignore Peggy's internal library mode and internal position/error options. No caller-supplied option other than the selected start rule may change parsing: `parse(input, { peg$library: true })` MUST NOT return the generator's internal library object, and `parse(input, { startRule, peg$currPos })` MUST parse from the start of the input.
- The parser module MUST expose exactly `parse`, `StartRules`, and `SyntaxError`. No additional export, duplicate `StartRules`, `toSource`, loader, alternate parser, or runtime fallback is permitted.
- `StartRules` MUST contain exactly the 226 rule names that the PEG.js 0.7.0 baseline accepted as independently selectable start rules, with no omissions and no additional names. A rule name that existed only as an alias in the baseline and could not be selected independently MUST NOT appear. Every listed name MUST be selectable through both historical call shapes.
- `StartRules` MUST be a snapshot of the declared start-rule names rather than a live switch: after the module is loaded, adding, replacing, or removing entries of the returned array MUST NOT change which rule names `parse` accepts, MUST NOT change a parse result, and MUST NOT change the error raised for an unknown rule name.
- `Grammar` MUST remain reachable through the JsSIP entry point, and `StartRules` and `SyntaxError` MUST remain part of the public surface.
- The parser declaration MUST declare only members provided by the parser module. In particular, it MUST NOT declare `toSource()` unless that member is actually available on the module's public surface.
- The TypeScript declaration MUST faithfully describe the public parser API: `parse` MUST accept both call shapes and every second-argument value the runtime accepts (including non-string primitives, functions, and boxed primitives); `StartRules` MUST be typed as a string array; `SyntaxError` MUST be declared as a class that is usable both as a constructor value and as an instance type, with its runtime `expected`, `found`, and `location` properties. Its declaration MUST include the static `buildMessage(expected, found)` method, whose `expected` parameter is a non-nullish array of expectations, the instance `format(sources)` method, and a constructor that accepts Peggy 4.2.0's four arguments `(message, expected, found, location)`. The constructor's `location` argument MUST accept Peggy's `source`, `start`, and `end` fields; no zero- or one-argument constructor overload is required.
- `SyntaxError.expected` MUST be typed as an array of Peggy's five discriminated expectation variants: `literal` with `text` and `ignoreCase`, `class` with `parts`, `inverted`, and `ignoreCase`, `any`, `end`, and `other` with `description`. Each `class.parts` member MUST be either a string or an exact two-element `[start, end]` string tuple, not an arbitrary-length `string[]`. The property MAY additionally allow `null` or `undefined` for compatibility, but neither the property nor its array element type may be `any`, `unknown`, `object`, a broad `{ type: string }`, or another type that loses the variant-specific fields.

## Behavior that must stay unchanged

- For every start rule, valid SIP URIs, headers, and messages MUST produce results that are semantically identical to the PEG.js 0.7.0 baseline: the same shape, keys, values, array order, numeric values, and handling of absent fields.
- Parsing the `Subscription_State` start rule MUST return an object whose `state` value is the parsed substate. For each of the `reason`, `expires`, and `retry_after` parameters present in the input, the result MUST contain a property with that same name and the baseline value and type; a parameter absent from the input MUST NOT cause its property to appear.
- Invalid input MUST keep the baseline failure semantics. A syntax error surfaced through `Grammar.parse(input, startRule)` MUST produce `-1`; every other exception MUST propagate with its original type and message, except that unknown start-rule errors MUST use the contract below. No other failure may be converted into `-1`, and no valid input may produce `-1`.
- Selecting an unknown start rule MUST throw a plain `Error` from both `parse(input, startRule)` and `parse(input, { startRule })`. Its message MUST be exactly `Invalid rule name: "<name>".`, and it MUST NOT return `-1`. The quoted name MUST use the PEG.js 0.7.0 string-quoting format: `"` becomes `\"`, `\` becomes `\\`, newline, tab, backspace, form feed, and carriage return become `\n`, `\t`, `\b`, `\f`, and `\r`, Latin-1 characters use uppercase `%XX`, and other non-ASCII BMP characters use uppercase `%uXXXX`.
- A non-string value supplied as the selected start rule MUST be converted with `String` before rule membership is checked, and error messages MUST quote that converted name. If the converted name is declared, it MUST select that rule exactly as the equivalent string value does; otherwise it MUST raise the same plain `Error` and message shape described above. For example, `parse(input, new String("CRLF"))` and `parse(input, { startRule: new String("CRLF") })` MUST select `CRLF`. The selected values `0`, `true`, `null`, `Symbol('x')`, and `{}` MUST produce `Invalid rule name: "0".`, `Invalid rule name: "true".`, `Invalid rule name: "null".`, `Invalid rule name: "Symbol(x)".`, and `Invalid rule name: "[object Object]".` respectively, because their converted names are not declared rules. These examples refer to a selected start-rule value, such as `{ startRule: null }`; a `null` second argument has the separate no-selection behavior below.
- A `null` second argument carries no start-rule selection: `parse(input, null)` MUST return exactly what `parse(input)` returns and MUST NOT surface an internal exception such as a `TypeError`.
- Start-rule membership MUST be based only on declared grammar rule names. Inherited object properties, including `constructor`, `toString`, `hasOwnProperty`, `valueOf`, and `__defineGetter__`, MUST be rejected as unknown rules even when an object prototype contains a property with that name.
- Behavior MUST remain equivalent for arbitrary and malformed inputs across all start rules, not only for curated examples. No start rule may be dropped, renamed, narrowed, or made unreachable.
- The public wrappers built on the grammar (`URI`, `NameAddrHeader`, `SIPMessage`, and `Parser`) MUST keep their observable parse results and error behavior for valid and invalid input.
- Loading the parser module MUST succeed without network access, without spawning processes, and without mutating global state.

## constraints

1. Do not retain PEG.js as an active dependency, generator, runtime, transitive dependency, alias, vendored copy, subprocess bridge, or dynamic loader.
2. Do not maintain parsing logic by hand in the generated parser artifact. The committed artifact MUST be the reproducible output of the grammar build; any compatibility behavior required by the public contract MUST be part of that reproducible output, not supplied by a separate hand-maintained parser or runtime fallback.
3. Do not modify, delete, rename, weaken, or skip existing tests, and do not add skip, only, or xfail markers.
4. Do not change unrelated public APIs, package metadata, or add dependencies that are not required for this migration.
5. Keep the change set inside the grammar-generation migration boundary.
6. Run the project's existing test suite and make it pass. A successful exit status alone is not sufficient evidence; the observable parse results must still match the baseline.
7. Rebuilding the grammar twice from the same source MUST produce byte-identical output, and the committed artifact MUST be that output with no residual diff.
