# Migrate Text Markdown rendering to markdown-it

## Task

Replace `marked` `^12.0.2` with `markdown-it` `14.1.0` in `@usewaypoint/block-text`. Remove the package's `marked` dependency. Production Markdown HTML must be generated by `markdown-it` and then sanitized by the existing `insane` configuration.

Preserve the public behavior below. Whitespace in generated Markdown HTML may differ only if the element tree, attributes, text after collapsing whitespace runs, and security behavior stay the same.

## Required behavior

- Keep the `Text` export, schema, `{ style, props }` invocation, style passthrough, and `renderToStaticMarkup` block structure. With `props.markdown=true`, `Text` renders through `EmailMarkdown`; with `false` or no `markdown` prop, it renders literal text in a `div` without invoking a Markdown parser. Bare URLs and strikethrough syntax stay literal in this plain-text path. Empty or null text produces an empty `div` in either mode.
- Keep `EmailMarkdown`'s component interface and styled `div` HTML injection. Its injected HTML must be the sanitized result of `markdown-it` rendering.
- In Markdown mode, render headings (`h1`–`h6`), ordered and unordered lists (`ol`, `ul`, `li`), strong and emphasized text (`strong`, `em`), links, images, and raw HTML. A single newline within a paragraph renders as `br`. Also support GFM tables, bare `http`/`https` URL autolinks, and `~~strikethrough~~` as `del`.
- Every GFM table must contain `table width="100%"`, `thead`, header `tr` and `th` elements, and `tbody`. Data rows use `tr` and `td` inside `tbody`. Left-, center-, and right-aligned columns must retain the corresponding `align="left"`, `align="center"`, or `align="right"` attribute on each header and body cell after sanitization. A table with a header and separator but no data rows must still have a `tbody` with no element children or non-whitespace text.
- Markdown links and bare `http`/`https` autolinks must have `target="_blank"`; bare URL links retain the original URL as `href`, and Markdown link titles remain present. An anchor supplied as raw HTML must not acquire a `target` attribute.
- Preserve the existing `insane` allowed tags, attributes, URL schemes, and missing `href`/`src` handling. Allow the existing `http`, `https`, and `mailto` cases; remove or empty blocked `javascript:`, `data:`, and `ftp:` URLs. The output must contain no executable `script` elements or event-handler attributes. Images and raw HTML still pass through the sanitizer.
- The built package must render Markdown through both its CJS and ESM entry points when used outside this repository with only its declared runtime and peer dependencies available.

## Constraints

1. Limit changes to `packages/block-text/src/EmailMarkdown.tsx`, `packages/block-text/package.json`, the existing `packages/block-text/src/__snapshots__/index.spec.tsx.snap`, and the `package-lock.json` entries needed for this migration.
2. Do not change the React wrapper, the plain-text `Text` path, the `insane` configuration, the Text schema, block IDs or `childrenIds`, the `renderToStaticMarkup` shell, or `examples/vite-emailbuilder-mui`.
3. Do not use `marked` in production, directly or through a subprocess, RPC, FFI, dynamic import, or another fallback. `markdown-it` must perform the in-scope Markdown parsing and rendering.
4. Keep the existing `react` and `zod` peer dependency ranges. Do not upgrade React, `zod`, `insane`, or unrelated dependencies. Keep the existing repository build configuration and root TypeScript and package `tsup` builds functional; the package build must produce CJS, ESM, and declaration files.
5. Do not delete, skip, or weaken existing public tests or snapshots. Update a snapshot only for permitted output differences: the same input must retain its element structure, attributes, text after collapsing whitespace runs, and security behavior. Do not remove assertions, weaken checks, or hardcode evaluation inputs to fake compliance.
6. Work in `/workspace/repo`. The evaluated result is the repository diff against the supplied starting commit.

## Validation

From `/workspace/repo`, run `npm test` (or `npx jest`), `npm run build --workspaces`, `npx eslint .`, `npx prettier . --check`, and `npx tsc --noEmit`.
