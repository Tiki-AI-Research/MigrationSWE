# Migrate the Field Theory CLI from TypeScript to Go

## Background

The Field Theory CLI (package `fieldtheory`, executables `ft` and `fieldtheory`) is a local-first command-line tool for X/Twitter bookmarks. It stores bookmarks as a JSONL cache, builds a SQLite FTS5 full-text index, and provides search, classification, Library and portable-command management, path diagnostics, and agent-facing context. It is currently written in TypeScript (`target: ES2022`, `module: NodeNext`, toolchain `6.0.2`) and runs on Node.js `>= 20`. Its runtime dependencies are `commander`, `dotenv`, `sql.js`, `sql.js-fts5`, and `undici`; SQLite is provided in WebAssembly with no native bindings.

## Goal

- Migrate the `fieldtheory` CLI from TypeScript/Node.js to Go `1.23.0`.
- The migration scope is the CLI entry point and the modules that implement the CLI surface, path/config resolution, the JSONL cache and SQLite FTS5 index, regex classification, the external LLM engine bridge, interactive prompts, preferences, and the Library/portable-command document layer: `bin/ft.mjs`, `src/cli.ts`, `src/companion-cli.ts`, `src/db.ts`, `src/bookmarks-db.ts`, `src/paths.ts`, `src/fs.ts`, `src/types.ts`, `src/date-utils.ts`, `src/bookmark-classify.ts`, `src/engine.ts`, `src/prompt.ts`, `src/preferences.ts`, `src/config.ts`, `src/library.ts`, `src/commands-files.ts`.
- The Go program MUST be the `ft` / `fieldtheory` executable and MUST carry the migrated responsibilities: the CLI command surface, local path resolution, the SQLite FTS5 index and its search/list/stats queries, regex classification, the external LLM engine invocation bridge, and the Library / portable-command CRUD layer.
- The following behaviors and features are out of scope and MUST NOT be required of the Go implementation: X GraphQL/OAuth network sync and browser-cookie extraction; `ft fetch-media` media downloads; `ft install app` and `app open` macOS app install/open; and browser-session / X API credential environment-variable behavior.

## Public contract to preserve

- `ft` and `fieldtheory` MUST remain the command names, and the CLI MUST accept the documented top-level commands and subcommands with their options and arguments, including the `--json` flag where documented, while keeping the distinction between JSON and human-readable text output.
- Command failures MUST exit non-zero; `ft commands validate` MUST exit non-zero when any inspected command fails validation; argument and parse errors MUST exit non-zero with a fix-oriented message.
- The hidden `ft bookmarks <cmd>` alias MUST forward to the corresponding top-level command for `sync`, `search`, `list`, `show`, `stats`, `viz`, `classify`, `classify-domains`, `categories`, `domains`, `folders`, `model`, `index`, `auth`, `status`, `path`, `sample`, and `fetch-media`, and `ft bookmarks enable` MUST forward to `ft sync`.
- Running `ft` with no arguments MUST show the first-run welcome when `bookmarks.jsonl` is absent, and the dashboard otherwise.
- SQLite index contract: a `meta` table (`key`, `value`) whose `schema_version` is `6`; a `bookmarks` table with the 37 columns `id, tweet_id, url, text, author_handle, author_name, author_profile_image_url, posted_at, bookmarked_at, synced_at, conversation_id, in_reply_to_status_id, quoted_status_id, language, like_count, repost_count, reply_count, quote_count, bookmark_count, view_count, media_count, link_count, links_json, tags_json, ingested_via, categories, primary_category, github_urls, domains, primary_domain, quoted_tweet_json, article_title, article_text, article_site, enriched_at, folder_ids, folder_names`; indexes on `author_handle`, `posted_at`, `language`, `primary_category`, and `primary_domain`; and a content-linked FTS5 virtual table `bookmarks_fts(text, author_handle, author_name, article_text)` declared `content=bookmarks, content_rowid=rowid, tokenize='porter unicode61'`, with search ranked by `bm25(bookmarks_fts, 5.0, 1.0, 1.0, 3.0)` in ascending order.
- Local state contract: the default root is `~/.fieldtheory`, with `bookmarks/bookmarks.jsonl` (one JSON record per line), `bookmarks/bookmarks.db`, `bookmarks/bookmarks-meta.json`, `bookmarks/.preferences`, `library/`, and `commands/`; the locations are overridable via `FT_DATA_DIR`, `FT_LIBRARY_DIR`, and `FT_COMMANDS_DIR` with the documented fallbacks. The CLI MUST read and write these on-disk formats so existing data remains usable.

## Behavior requirements

- Path resolution: `FT_DATA_DIR` overrides the bookmark data root; without it the canonical `~/.fieldtheory/bookmarks` is used unless only the legacy `~/.ft-bookmarks` exists. `FT_LIBRARY_DIR` overrides the Library root, `FT_COMMANDS_DIR` overrides the commands root, and when only `FT_DATA_DIR` is set the Library root is `<FT_DATA_DIR>/md`; the default commands root is `<library>/Commands` with a legacy `~/.fieldtheory/commands` fallback. `ft path` MUST print the active data directory, and `ft paths --json` MUST report the active, canonical, environment, and legacy path fields.
- Index rebuild: `ft index` MUST read `bookmarks.jsonl` and write `bookmarks.db`, set `meta.schema_version = 6`, and report total and newly added record counts; refreshing existing rows MUST preserve previously stored classification, enrichment, and folder columns, while `--force` MUST drop and rebuild the tables. Schema migrations MUST be driven by actual column existence (self-healing) and MUST rebuild the FTS index only when the `article_text` column is missing.
- Search: `ft search <query>` MUST apply FTS5 matching with the BM25 weights above and return matched bookmarks; `--author`, `--after`, and `--before` filters MUST apply, and the default limit MUST be `20`. FTS5 operator input MUST be sanitized into literal terms, and an unparseable query MUST produce a readable `Invalid search query` error. An empty result set MUST format as `No results found.`
- List and show: `ft list` MUST support `--query`, `--author`, `--after`, `--before`, `--category`, `--domain`, and `--folder` (exact or unambiguous prefix) with default limit `30` and offset `0`; `ft show <id>` MUST print one bookmark in detail and, for an unknown id, print a not-found message and exit non-zero.
- Aggregates: `ft stats` MUST report total bookmarks, unique authors, the earliest/latest date range derived from `posted_at`, the top authors (limit 15), and the language breakdown (limit 10). `ft categories` and `ft domains` MUST report distributions sorted by count, `ft categories` MUST exclude the `unclassified` placeholder, and `ft folders` MUST report per-folder counts plus an untagged count.
- Regex classification: `ft classify --regex` MUST classify each bookmark into the categories `security`, `tool`, `technique`, `launch`, `research`, `opinion`, and `commerce`, selecting the primary category by that priority order or `unclassified` when none match, and MUST report a summary of classified and unclassified counts.
- LLM engine bridge: engines `claude` and `codex` MUST be detected on `PATH` (honoring `PATHEXT` on Windows). Resolution MUST prefer an explicit `--engine`/override (failing fast when unknown or not on `PATH`), then a saved default that is available, then a single available engine, then a TTY prompt in the order `claude`, `codex` with the choice persisted, and otherwise the first available. The claude argument form MUST be `-p --output-format text [--model <model>] [--effort <effort>] <prompt>` and the codex argument form MUST be `exec --skip-git-repo-check [--model <model>] [--config model_reasoning_effort="<effort>"] <prompt>`; the engine label MUST be `name[/model][/effort=<effort>]`.
- Engine invocation: invocation MUST close the child's stdin immediately so reading children see EOF, MUST return trimmed stdout on a zero exit, and on failure MUST raise a structured `EngineInvocationError` carrying `reason` (`timeout`, `maxbuffer`, `exit`, or `spawn`), a `killed` flag, exit code/signal, and bounded, secret-redacted stderr. The default timeout MUST be `120000` ms and the default stdout buffer cap MUST be `1 MiB`; a timeout MUST terminate the child (SIGTERM, escalating to SIGKILL after about 2 seconds); exceeding the buffer cap MUST be reported as `maxbuffer`; stderr reported to the user MUST be clipped to a tail. Failure messages MUST NOT inline the prompt, and provider-prefixed keys (`sk-...`), GitHub tokens (`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`), and `Bearer` tokens MUST be redacted.
- Prompts: the interactive prompt helper MUST resolve to the trimmed answer, to `close` when the interface closes without an answer, and to `interrupt` (and close the interface) on SIGINT.
- Preferences: `.preferences` MUST load as an empty object when missing or invalid, and saving MUST create the data directory and write the file owner-only (`0600`) on POSIX.
- Filesystem layer: JSON and JSONL writes MUST default to `0600` and be crash-durable (write to a temp file, fsync, rename, then fsync the parent directory); Markdown writes MUST use `0644`; reading a missing or malformed JSONL file MUST yield an empty list.
- Library documents: `ft library` create/show/update/rename/delete/search/list MUST operate under the canonical Library root, MUST reject path traversal, and MUST exclude hidden directories and the internal context sessions directory by default; update MUST refuse empty content and MUST require either an `--expected-sha256` that matches the current file or `--force`; delete MUST move the file to the user's Trash.
- Portable commands: `ft commands` new/show/update/rename/delete/list/validate MUST operate under the commands root; names MUST reject path separators, absolute paths, and names beginning with `.` or `_`; validation MUST check for a top-level heading, "Use this when" guidance, a `## Steps` section, a `## Guardrails` or `## Safety` section, concrete verification guidance, and the absence of secret-like values.
- Date helpers: timestamp parsing MUST accept the formats the existing cache contains, and date, month, weekday, UTC hour, year, and month/day labels MUST be derived in UTC with the existing fallbacks for unparseable values.
- Legacy ideas data: the one-time migration from `<data-dir>/automation/{ideas,adjacent}` to `<root>/ideas` MUST be idempotent, MUST use an in-progress marker and a completion marker, MUST recover by wiping and retrying after an interrupted run, and MUST leave a user-populated target untouched.
- Environment loading: configuration loading MUST read `.env.local` then `.env` from the current working directory and then from the data directory, without overriding values already present.

## Constraints

1. The migration MUST NOT remove required public capabilities or change their contracts outside the stated goal.
2. Production code within the migration scope MUST NOT import, require, or otherwise call TypeScript or the Node.js runtime to perform migrated responsibilities.
3. The implementation MUST NOT delegate migrated responsibilities to the TypeScript/Node.js runtime through subprocesses, RPC, FFI, dynamic loading, or wrapper executables.
4. The result MUST be a real Go `1.23.0` implementation; renaming files, deleting capabilities, or wrapping the existing implementation does not satisfy the goal.
5. Changes MUST be limited to the Go implementation, its module and build configuration, and supporting repository assets; you MAY add Go build/test wiring but MUST NOT change the behavioral assertions of the existing public tests.
6. Source-framework code and dependencies outside the migration scope (X GraphQL/OAuth sync, browser-cookie extraction, media downloads, macOS app install/open, and credential environment behavior) MAY remain and are not required to be migrated.
7. Protected public assets are the documented `ft` command surface, the JSONL/metadata formats, the SQLite schema (`schema_version = 6`, the content-linked FTS5 table, and the BM25 weights), and the `~/.fieldtheory` layout; do not alter these or hidden evaluation assets.
8. You MUST NOT skip checks, remove assertions, weaken comparisons, or hardcode evaluation inputs to fake compliance.
9. Work in the `/workspace/repo` working directory and keep all deliverable files inside the repository working tree; changes are collected from the working tree relative to the task's start commit, and no branch or commit is required.
10. The build and evaluation environments are offline and self-contained: there is no network access during a trial, no package installation is performed, and no native system libraries are provided. The Go program MUST build (`go build ./...`) and run using only the toolchain and dependency cache already present in the environment, without fetching anything at build or run time.

## Validation

From `/workspace/repo`, run `npm test`. This runs the repository's existing public test suite (Node.js `node:test` executed through `tsx`) and documents the expected behavior of the in-scope modules; it exercises the TypeScript implementation and does not by itself verify a Go implementation. Separately, the Go program MUST build with the Go `1.23.0` toolchain and run as the `ft`/`fieldtheory` entry point so the documented commands can be exercised against a temporary data directory.
